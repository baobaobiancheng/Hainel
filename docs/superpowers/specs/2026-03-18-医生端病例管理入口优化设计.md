# 医生端病例管理入口优化设计方案

## 背景

当前医生端在新建病历时，需要手动输入患者 ID 才能创建病历。这一设计存在以下问题：

1. **用户体验差**：医生需要记住或查询患者的 ID 才能创建病历
2. **不符合业务流程**：医生通常先在患者列表中找到患者，再为该患者创建病历

## 目标

优化医生端病历创建流程，减少手动操作，提升用户体验。

## 设计方案

### 改动概述

在患者列表页面（Patients.vue）增加"新建病历"入口，医生可以直接为指定患者创建病历。

### 详细设计

#### 1. 前端改动

**1.1 Patients.vue - 操作列增加按钮**

在患者列表的操作列增加"新建病历"按钮，点击后执行以下逻辑：

- 查询该患者是否已有病历记录
- 如果有 → 跳转到病历管理页面，并自动筛选该患者的病历，显示提示"该患者已有病历记录"
- 如果没有 → 打开新建病历弹窗，自动填充 patient_id

**1.2 Records.vue - 新建病历弹窗改造**

- 移除手动输入的"患者 ID"字段
- 支持从路由参数接收 patient_id，自动填充
- 如果 patient_id 来自路由，显示关联的患者信息

#### 2. 后端改动

**2.1 病历列表 API**

确保支持 `patient_id` 筛选参数，用于从患者列表跳转到病历页面时自动筛选。

**2.2 患者病历检查 API**

新增或利用现有接口，返回指定患者的病历数量。

### 交互流程

```
患者列表页 → 点击"新建病历" → 检查该患者是否有病历
                                      │
                    ┌─────────────────┴─────────────────┐
                    │                                       │
              有病历记录                              无病历记录
                    │                                       │
     跳转到病历页面 + 筛选该患者 + 提示消息         打开新建病历弹窗
                                                        (自动填充 patient_id)
```

## 验收标准

1. 医生可以在患者列表中直接为患者创建病历
2. 如果患者已有病历，跳转时自动筛选并提示
3. 新建病历时无需手动输入患者 ID
4. 现有功能不受影响

## 影响范围

- frontend-doctor/src/views/Patients.vue
- frontend-doctor/src/views/Records.vue
- 后端病历列表 API（如需支持 patient_id 筛选）
