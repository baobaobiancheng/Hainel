# PDF及文档识别功能设计

## 1. 需求概述

### 1.1 需求背景

现有系统已实现图片格式的OCR识别功能，支持患者上传检查报告图片并进行文字识别。为进一步提升用户体验，需要支持PDF格式文档的识别功能。

### 1.2 需求目标

- 支持患者上传PDF格式的检查报告
- 复用现有的DashScope OCR API（qwen-vl-plus）进行识别
- 利用Qwen-VL-Plus的高精度表格识别与版式理解能力
- 提供与现有图片识别一致的API接口

## 2. 技术方案

### 2.1 整体架构

```
患者上传PDF文件
      ↓
PDF转图片（每页一张图，使用pdf2image）
      ↓
调用现有 DashScope OCR API（qwen-vl-plus）
      ↓
整合多页识别结果 → 返回结构化文本
```

### 2.2 技术选型

| 模块 | 技术选型 | 说明 |
|------|----------|------|
| PDF处理 | `pdf2image` + `poppler` | 将PDF每页转为PIL Image |
| 图片格式转换 | PIL Image | 转JPEG格式适配现有API |
| OCR识别 | 复用现有 `DashScopeOCRService` | qwen-vl-plus 已支持表格和版式理解 |
| 多页合并 | 字符串拼接 + 分页标记 | 合并多页识别结果 |

### 2.3 核心技术点说明

#### 2.3.1 PDF转图片

使用`pdf2image`库将PDF文档的每一页转换为PIL Image对象：

```python
from pdf2image import convert_from_bytes

# 从字节流转换
images = convert_from_bytes(pdf_bytes)
# 从文件路径转换
images = convert_from_path(pdf_file_path)
```

#### 2.3.2 复用现有OCR API

现有的`DashScopeOCRService`已使用qwen-vl-plus模型，该模型具备：
- 高精度文字识别
- 表格识别与结构化输出
- 版式理解（Layout Understanding）
- 中文文档场景业界第一梯队

直接复用现有服务，无需额外API配置。

#### 2.3.3 多页文档处理

- 逐页识别：遍历PDF每一页，调用OCR API
- 结果合并：使用分页标记（如"--- 第 X 页 ---"）合并多页结果
- 异常处理：单页识别失败不影响其他页面

## 3. API设计

### 3.1 接口定义

```
POST /api/reports/ocr
Content-Type: multipart/form-data
```

#### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| file | File | 是 | 上传的PDF文件 |

#### 响应结果

```json
{
  "code": 200,
  "message": "识别成功",
  "data": {
    "text": "完整识别的文本内容（含表格结构）",
    "confidence": 0.95,
    "page_count": 3,
    "metadata": {
      "model": "qwen-vl-plus",
      "usage": {...}
    }
  }
}
```

### 3.2 错误处理

| 错误码 | 说明 |
|--------|------|
| 400 | 文件格式不支持（非PDF） |
| 400 | PDF文件为空或损坏 |
| 413 | 文件大小超限 |
| 500 | OCR识别服务内部错误 |
