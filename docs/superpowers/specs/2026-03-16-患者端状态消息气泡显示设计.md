# 患者端状态消息对话气泡显示设计

## 1. 概述

将患者端咨询页面的状态提示从顶部状态栏和 `wx.showLoading` 加载框改为对话气泡形式，类似于微信聊天的消息显示，让患者更直观地了解咨询进度。

## 2. 目标

- 提升用户体验，将进度信息以更自然的方式展示
- 减少弹窗干扰，使用户专注于对话流程
- 与整体聊天界面风格保持一致

## 3. 状态类型定义

> **注意**：与现有代码中的状态名称保持一致

| 状态 | 消息文本 | 气泡样式 |
|------|---------|---------|
| `analyzing` | 🔄 正在分析您的症状... | 浅蓝色 |
| `pending_review` | 📋 智能分析完成，等待医生审核 | 浅黄色 |
| `reviewing` | 👨‍⚕️ 医生正在审核诊断... | 浅绿色 |
| `completed` | ✅ 诊断已完成 | 浅绿色 |

## 4. 前端实现

### 4.1 数据结构

在消息列表中增加系统状态消息类型：

```javascript
// 消息对象结构
{
  id: 'status-{uuid}',
  role: 'assistant',  // 复用现有 assistant 角色，使用 message_type 区分
  message_type: 'status',
  status: 'pending_review',  // 状态标识
  content: '智能分析完成，等待医生审核',  // 显示文本
  agent_name: '系统',  // 显示名称为"系统"
  timestamp: '2024-01-01T12:00:00Z'
}
```

> **兼容性说明**：使用 `role: 'assistant'` 复用现有渲染逻辑，`message_type: 'status'` 用于区分普通AI消息和状态消息。`agent_name` 设置为"系统"以明确来源。

### 4.2 修改文件

#### consultation.wxml

在现有消息列表中，已有根据 `item.role` 区分左右位置的逻辑。由于我们使用 `role: 'assistant'`，状态消息会显示在左侧。需要在气泡渲染部分添加对 `message_type === 'status'` 的特殊处理：

```xml
<!-- 在现有气泡渲染逻辑中添加 status 样式类 -->
<view class="bubble bubble--{{item.role === 'user' ? 'user' : 'ai'}} {{item.message_type === 'status' ? 'bubble--status bubble--status-' + item.status : ''}}">
  <text class="bubble-text" selectable>{{item.content}}</text>
</view>
```

> **简化处理**：直接复用现有气泡样式，通过添加 `bubble--status` 修饰类和状态颜色类来实现不同样式。

#### consultation.js

修改 `handleWsMessage` 方法：

1. 移除 `wx.showToast` 调用（诊断完成时的 toast 仍保留）
2. 将状态消息添加到消息列表
3. 保留顶部状态栏用于简单状态显示，但主要通过气泡展示

```javascript
handleWsMessage(data) {
  // 处理状态更新
  if (data.type === 'status_update') {
    this.handleStatusUpdate(data)
    return
  }
  // ... 其他消息处理
},

handleStatusUpdate(data) {
  // 使用浅拷贝创建新数组，避免直接修改原始数据
  const statusMessages = [...this.data.messages]
  const existingStatusIndex = statusMessages.findIndex(
    m => m.message_type === 'status'
  )

  const statusMsg = {
    id: `status-${Date.now()}-${Math.random().toString(36).substr(2, 9)}`,
    role: 'assistant',
    message_type: 'status',
    status: data.status,
    content: data.message,
    agent_name: '系统',
    timestamp: new Date().toISOString()
  }

  if (existingStatusIndex >= 0) {
    // 更新现有状态消息
    statusMessages[existingStatusIndex] = statusMsg
  } else {
    // 添加新状态消息
    statusMessages.push(statusMsg)
  }

  this.setData({ messages: statusMessages })
  this.scrollToBottom()

  // 诊断完成时刷新消息列表（清除状态消息，显示真实AI回复）
  if (data.status === 'completed') {
    setTimeout(() => {
      this.loadMessages()
    }, 2000)
  }
}
```

**移除 wx.showLoading 的位置：**

1. `sendMessage` 方法第289行：移除 `wx.showLoading({ title: '智能分析中...', mask: true })`
2. `handleWsMessage` 方法第176-180行：移除 `wx.showToast` 调用

**关于 wx.showModal：**
- 保留第186-191行的 `wx.showModal`，因为这是诊断完成后的确认弹窗，属于必要的用户确认流程

## 5. 后端（无需修改）

后端已支持通过 WebSocket 推送 `status_update` 消息，前端只需正确处理即可。

## 6. 边界情况处理

| 边界情况 | 处理方式 |
|---------|---------|
| WebSocket 断开 | 顶部状态栏保留显示连接状态，气泡消息保持直到新状态到来 |
| 网络超时 | 后端已有超时处理，前端显示最后的状态消息 |
| 状态乱序 | 后端保证顺序推送，前端不做额外处理 |
| 页面切换 | onHide 时保持状态消息，onShow 时通过 loadMessages 刷新 |

## 7. 测试要点

1. 患者发送症状后，状态消息是否正确显示在对话窗口
2. 各个状态阶段是否显示正确的背景色
3. 状态更新时是否正确更新而非重复添加
4. 诊断完成后是否正常刷新消息列表
5. WebSocket 断开重连后状态是否正常

## 7. 预期效果

- 患者发送症状后，对话窗口显示 "🔄 正在分析您的症状..."
- 智能分析完成后，状态更新为 "📋 智能分析完成，等待医生审核"
- 医生开始审核后，状态更新为 "👨‍⚕️ 医生正在审核诊断..."
- 诊断完成后，状态更新为 "✅ 诊断已完成"，2秒后刷新消息列表显示完整诊断结果
