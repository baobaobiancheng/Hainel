## 2. 核心模块详细设计

### 2.1 后端核心模块

#### 2.1.1 API路由层（app/api/）

**职责**：处理HTTP请求，参数验证，调用服务层

**设计原则**：
- 每个资源对应一个路由文件
- 使用FastAPI的依赖注入进行认证和权限检查
- 统一的错误处理和响应格式
- API版本化管理（v1, v2...）

**关键文件**：
- `auth.py`: 登录、注册、Token刷新
- `conversations.py`: 会话创建、查询、状态管理
- `messages.py`: 消息发送、接收、历史查询
- `medical_records.py`: 病历CRUD、审核、归档
- `agents.py`: 智能体管理、状态查询、配置更新

#### 2.1.2 业务服务层（app/services/）

**职责**：实现核心业务逻辑，协调多个数据模型和外部服务

**设计原则**：
- 一个服务类对应一个业务领域
- 服务之间通过接口调用，避免直接依赖
- 事务管理在服务层
- 异步操作使用Celery任务

**关键服务**：
- `conversation_service.py`: 会话生命周期管理，智能体调度触发
- `medical_record_service.py`: 病历生成、结构化、审核流程
- `knowledge_service.py`: 知识库查询、缓存管理

#### 2.1.3 多智能体系统（app/agents/）

**职责**：实现MDAgents框架的自适应多智能体协作机制

**模块划分**：

1. **base/** - 智能体基础设施
   - `agent_base.py`: 所有智能体的抽象基类，定义统一接口
   - `agent_interface.py`: 智能体接口规范（process、respond、evaluate等）
   - `message.py`: 智能体间消息格式定义

2. **moderator/** - 调节器代理
   - `moderator_agent.py`: 接收查询，评估复杂度，路由决策
   - `complexity_evaluator.py`: 复杂度评估算法（LLM + 规则引擎）
   - `router.py`: 根据复杂度选择PCC/MDT/ICT模式

3. **pcc/** - PCC模式（低复杂度）
   - `pcc_agent.py`: 单个智能体独立处理
   - `cot_reasoning.py`: 思维链推理实现
   - `self_consistency.py`: 自一致性验证（多次采样取共识）

4. **mdt/** - MDT模式（中复杂度）
   - `mdt_team.py`: 团队管理（3-5个智能体）
   - `mdt_agent.py`: MDT智能体实现（参与讨论）
   - `consensus.py`: 共识达成算法（≥60%一致）
   - `discussion.py`: 迭代讨论流程（最多3轮）

5. **ict/** - ICT模式（高复杂度）
   - `ict_team.py`: 团队管理（5-7个智能体）
   - `ict_agent.py`: ICT智能体实现
   - `phase_manager.py`: 三阶段处理管理
   - `report_synthesizer.py`: 综合报告生成

6. **specialty/** - 专科智能体
   - `base_specialty.py`: 专科智能体基类
   - `cardio_agent.py`: 心血管专科（CardioMind）
   - 其他专科：可扩展（内分泌、神经等）

7. **patient_simulator/** - 患者模拟智能体
   - `patient_agent.py`: 模拟患者响应
   - `symptom_releaser.py`: 动态症状释放策略
   - `pathology_consistency.py`: 病理一致性保证
   - `case_generator.py`: 训练用例生成

8. **orchestrator/** - 智能体编排器
   - `agent_orchestrator.py`: 智能体生命周期管理
   - `team_builder.py`: 根据复杂度构建团队
   - `communication.py`: 智能体间通信（消息队列、Redis）

9. **evaluation/** - 评估与优化系统
   - `reward_calculator.py`: 多维度奖励计算
   - `accuracy_evaluator.py`: 诊断准确性评估（F1分数）
   - `efficiency_evaluator.py`: 信息获取效率评估
   - `compliance_evaluator.py`: 规范遵循评估
   - `training_manager.py`: 训练流程管理
   - `rl_trainer.py`: GRPO强化学习训练器
   - `sft_trainer.py`: 监督微调训练器
   - `performance_monitor.py`: 性能指标监控

#### 2.1.4 NLP处理模块（app/nlp/）

**职责**：文本处理、信息抽取、病历结构化

**关键模块**：
- `ner.py`: 医疗命名实体识别（症状、疾病、药物等）
- `relation_extraction.py`: 实体关系抽取
- `medical_record_parser.py`: 从主诉文本提取结构化信息

## 3. 模块间依赖关系

┌─────────────────────────────────────┐

│  └─ 依赖: 数据库模型                 │
├─────────────────────────────────────┤
│  AI模型服务 (app/ai/)                │  ← 模型调用

│  知识库 (app/knowledge/)             │  ← 知识检索

│  数据库访问层 (app/database/)        │  ← 数据持久化

6. **服务层 → 数据库模型**：数据CRUD操作

## 4. 扩展性设计

### 4.1 智能体扩展

**添加新智能体的步骤**：
1. 继承 `agents/base/agent_base.py` 或 `agents/specialty/base_specialty.py`
2. 实现必需的接口方法（process、respond等）
3. 在 `agents/orchestrator/team_builder.py` 中注册
4. 配置智能体元数据（名称、专业领域、能力描述）

**示例扩展点**：
- 新增专科智能体：在 `agents/specialty/` 下创建新文件
- 新增协作模式：创建新的模式目录（如 `agents/custom_mode/`）

### 4.2 API扩展

**添加新API的步骤**：
1. 在 `app/api/v1/` 下创建新的路由文件
2. 定义Pydantic Schema（请求/响应）
3. 创建对应的Service类
4. 在 `app/main.py` 中注册路由

### 4.3 数据库扩展

**添加新数据表的步骤**：
1. 在 `app/models/` 下创建新的模型类
2. 创建对应的Schema类
3. 使用Alembic生成迁移脚本
4. 更新Service层添加CRUD操作

### 4.4 AI模型扩展

**添加新AI模型的步骤**：
1. 在对应的目录下（`llm/`、`ocr/`等）创建新的服务类
2. 继承基类，实现统一接口
3. 在配置文件中添加模型配置
4. 通过依赖注入使用

## 6. 通信机制设计

### 6.1 智能体间通信

**同步通信**（PCC模式）：
- 直接函数调用
- 适用于单个智能体场景

**异步通信**（MDT/ICT模式）：
- 消息队列（RabbitMQ/Kafka）
- Redis Pub/Sub
- 适用于多智能体协作

**消息格式**：
```python
{
    "message_id": str,
    "session_id": str,
    "sender": str,  # 智能体名称
    "receiver": str | "broadcast",
    "message_type": str,  # analysis/question/consensus/report
    "content": dict,
    "metadata": dict
}
```

### 6.2 前后端通信

**HTTP API**：
- RESTful API（JSON格式）
- 统一响应格式
- JWT认证

**WebSocket**：
- 实时对话（患者端咨询）
- 消息推送（医生端通知）

本代码框架设计遵循以下原则：

1. **模块化**：每个功能模块独立，职责清晰

该框架支持：
- 快速开发新功能
- 灵活切换AI模型
- 动态添加智能体
- 水平扩展系统容量
- 持续优化和迭代
